# Audit and verification — 1 October 2026

This audit resumes the interrupted framework work. It checks the user's recorded requirements against the implemented core, portable presentation runtime, creator workflow, integration source, tests, and the larger proposed specification. **The full proposal is not completely implemented.** The table below distinguishes working features from remaining product work; a passing test is not a blanket conformance claim.

## Changes made in this audit

- Fixed repeated video-poster leases, stale cache-entry deletion, post-disposal work, snapshot scheduling, and resource counters after disposal.
- Counted text textures against the shared memory limit; validated stage budgets; made budget changes release/reload resources; removed the minimum DPR floor that could violate a small budget. Added a quality-governor cooldown.
- Fixed alpha-mask inversion and polygon masks on cropped atlas images. Added per-node nearest/linear GPU sampling and actual scene background rendering. Unsupported isolated group compositing now fails explicitly.
- Implemented declared optional-adapter omission/static fallback behavior.
- Made directory disposal abort network work. Verified directory dependency closure and manifest/index agreement before media loading; applied nested GLB/dotLottie validation to selectively fetched assets too.
- Tightened GLB embedded buffer/image/hierarchy checks, rejected external Lottie fonts/oversized inline rasters/duplicate IDs, and repaired adapter cleanup on failed or cancelled initialization.
- Snapshotted batch requests and exports against concurrent edits; rejected inherited importer/effect/preset names and transforms that rewrite requested card identities. Undo now restores modified asset bytes too.
- Added transactional poster replacement and Studio **Capture posters**, with both faces rendered at neutral input. Serialized toolbar actions after a browser regression exposed an overlapping-action race.
- Made the default card grid load/release posters by viewport. Fixed a hidden program restarting on a document visibility event.
- Fixed import-store initialization lock cleanup, cancellation of ready jobs, hung scanner shutdown, and compile cancellation after an asynchronous media processor.
- Exposed documented presentation submodules through root package exports; updated lifecycle return contracts and examples.

These are framework/runtime changes. Approved card artwork and the two immutable companion package digests were preserved outside code repositories.

## Remaining product gaps, in priority order

1. **Production integration:** mount presentation routes behind the chosen identity/origin/rate-limit policy; supply sandboxed scanning, durable publication credentials and storage. Add staff review/approval records and a role/suspension console if the reference host is expected to manage these itself. The current API hooks exist; these deployment and administration workflows are not complete.
2. **Physical mobile qualification:** sustained profiling on actual iPhone hardware in ordinary/low-power states, video codec failures and memory pressure. Do not infer this from desktop WebKit.
3. **Creator quality tools:** frame onion skin/contact-anchor UI, drag pivots/travel bounds, automatic seam diagnostics, parameterized templates/versioned recipe upgrades, richer structured per-layer publish warnings and editor extension panels. Mask painting, frame import, numeric/motion controls, drafts and explicit two-face poster capture work today.
4. **Rendering breadth:** isolated group compositing, explicit nonrectangular trim/hit regions, deterministic bundled fonts, calibrated linear-light/HDR, additional mask channels/maps, prewarm/edge geometry and a second backend. Unsupported isolated group effects now reject instead of silently losing meaning.
5. **Operations:** automatic safe recovery of a stale single-writer lock, durable service credentials/outbox, normalized high-volume/distributed storage and complete retention/reference registration. Current reference service is single-process and review-only for deletion.

This list is deliberately not converted into fake completed checkboxes. The broad proposal must stay marked proposed until these gaps are implemented and verified.

## Reproducible test commands

From the framework checkout (Node 24):

```sh
pnpm install --frozen-lockfile
pnpm --dir src/presentation install --frozen-lockfile
pnpm test
pnpm run test:spec
pnpm run test:coverage
pnpm exec playwright install chromium firefox webkit
node test/presentation-audit-browser.mjs ./node_modules/playwright/index.mjs test-results chromium
node test/presentation-audit-browser.mjs ./node_modules/playwright/index.mjs test-results firefox
node test/presentation-audit-browser.mjs ./node_modules/playwright/index.mjs test-results webkit
```

The standalone suite creates a temporary HTTP server and synthetic card/media fixtures, checks pixels with `readPixels`, exercises lifecycle/resource invariants and a real 1000-element gallery, writes a JSON report and closes its browser/server. It requires no Maple assets, Site, external credentials or optional art download. Chromium can use installed Edge when its bundled browser is absent. A missing browser is an error, not a silently passing skip. CI adds a separate engine matrix and uploads each report.

Integration scripts require the locally staged Site and optional fixtures outside Git:

```sh
node test/presentation-browser.mjs PLAYWRIGHT_MODULE http://127.0.0.1:4173/portable.html QA_FOLDER
node test/presentation-studio-browser.mjs PLAYWRIGHT_MODULE http://127.0.0.1:4173/studio.html QA_FOLDER
node test/presentation-layered-browser.mjs PLAYWRIGHT_MODULE http://127.0.0.1:4173/studio.html QA_FOLDER
node test/presentation-advanced-browser.mjs PLAYWRIGHT_MODULE http://127.0.0.1:4173/portable.html QA_FOLDER
node test/presentation-program-browser.mjs PLAYWRIGHT_MODULE http://127.0.0.1:4173/portable.html QA_FOLDER
node test/presentation-host-browser.mjs PLAYWRIGHT_MODULE http://127.0.0.1:4173 QA_FOLDER
node test/presentation-resilience-browser.mjs PLAYWRIGHT_MODULE http://127.0.0.1:4173/portable.html QA_FOLDER 900 300
```

`presentation-advanced-browser.mjs` requires the reviewed official Rive `ball.riv` fixture in QA_FOLDER. It is not hidden inside the framework repository. Other media probes generate synthetic data. Real-art reports and screenshots stay in `outputs/PortableCardQA`; no generated media is committed to framework Git.

The long run is checkpoint evidence, not a falsely labeled exact-final-build/device certification.
